## Defect

Submitting the custom-basemap editor with an empty or invalid tile URL moved focus to the URL input and posted a global status, but the responsible control did not expose `required`, `aria-invalid`, or an associated error. Attribution-link failures also returned focus to the tile URL instead of the invalid attribution field. On mobile, opening the editor while Feature Details was visible left the drawer over the editor, obscuring its fields and actions.

## Fix and regression coverage

- Added durable help and field-local live error elements for both URL controls.
- Synchronized visible error styling with `aria-invalid`.
- Focuses and explains the exact failing field.
- Clears stale error state as the user edits and before each new validation pass.
- Closes Feature Details before opening the custom-basemap editor, preventing the mobile sheet overlap.
- Expanded the required custom-basemap Production CI test to cover markup, field-state synchronization, focus recovery, and stale-error cleanup.

## Human inspection

1. Create a browser-only project.
2. Open **View → Map Type → Custom…**.
3. Choose **Save & use** with the tile URL empty; confirm the tile URL is focused, outlined red, and announces the inline error.
4. Enter `https://tiles.example/{z}/{x}/{y}.png`, then enter `http://provider.example` as the attribution link and save.
5. Confirm the attribution link—not the tile URL—is focused and explained.
6. Edit each invalid value and confirm its stale error clears immediately.

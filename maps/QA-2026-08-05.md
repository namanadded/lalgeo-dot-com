## Defect and fix

The one-shot **My Location** and route-acquisition flows already used durable status regions, but **Start Voice Navigation** bypassed that recovery model. A watcher failure interrupted users with a browser alert and left the route sidebar without an actionable state.

The fix adds a complete voice-navigation state machine:

- loading, active, error, and stopped announcements in the route sidebar;
- disabled/busy start and enabled stop states that prevent duplicate watchers;
- plain-language geolocation errors and a focused Try again action;
- empty-route and unsupported-browser recovery;
- watcher and speech cleanup on errors and Stop Voice;
- focus restoration to the invoking Start Voice Navigation button;
- shared behavior for initial and alternate-route render paths.

Failure evidence: `maps/screenshots/voice-navigation-location-recovery-production-2026-08-05.jpg` captures the production location recovery surface used as the expected non-blocking model; the voice-navigation branch did not provide an equivalent surface before this fix.

## Human inspection

1. Open the deploy preview, search for a destination, and choose **Get Directions**.
2. When a route appears, choose **Start Voice Navigation** and deny location access (or force unavailable/timeout).
3. Confirm the start button becomes busy while waiting, then the sidebar shows **Voice navigation unavailable** with **Try again** focused; no browser alert appears.
4. Allow location and retry. Confirm the sidebar announces **Voice navigation active**, Start is disabled, and Stop Voice is enabled.
5. Choose **Stop Voice**. Confirm tracking/speech stop, the stopped status is announced, and focus returns to Start Voice Navigation.
6. Select an alternate route and repeat to verify the same behavior.

Risk is limited to route voice-navigation controls and geolocation watcher lifecycle. Project formats, feature data, imports/exports, cloud storage, MapKit routing, and production settings are unchanged.

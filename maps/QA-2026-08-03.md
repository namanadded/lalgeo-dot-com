# Maps QA — 2026-08-03

## Scale and cloud reliability

### Change

Cloud catalog pagination now fails closed when a provider repeats a cursor, omits a required cursor, exceeds an explicit page/entry/result budget, or the caller cancels. Dropbox discovery uses provider-specific limits of 2,000 pages, 250,000 examined entries, and 50,000 matched projects. The shared adapter remains provider-independent for future authorized providers.

### Baseline and result

The previous cursor walker trusted `hasMore` indefinitely. A provider returning the same cursor could issue requests forever while retaining every unique matching row. The new synthetic repeated-cursor benchmark terminates after exactly two provider calls at every size:

| Synthetic project entries per page | Baseline calls | Result calls | Result time | Heap delta |
| ---: | ---: | ---: | ---: | ---: |
| 1,000 | unbounded | 2 | 1.41 ms | 0.24 MiB |
| 10,000 | unbounded | 2 | 5.47 ms | 6.93 MiB |
| 50,000 | unbounded | 2 | 34.75 ms | 25.20 MiB |

The existing 1,000 / 10,000 / 50,000 feature benchmark used 0.24 / 3.63 / 30.44 MiB projects. At 50,000 features: startup parse 46.32 ms, import 51.67 ms, pan/zoom scan 4.50 ms, render projection 0.82 ms, autosave 66.75 ms, export 49.75 ms, recovery parse 30.72 ms, serialization heap delta 60.85 MiB, and quota recovery preserved prior bytes.

The scoped catalog benchmark at one million unrelated files remained two pages and 120 examined entries (0.07 ms, 0.08 MiB measured heap delta), versus the synthetic recursive baseline of 502 pages and 1,000,240 examined entries.

### Compatibility and data-loss risk

Normal Dropbox pagination and project content are unchanged. Accounts exceeding the explicit catalog limits now receive an error instead of a partial or indefinitely growing list; no project bytes are opened, changed, or deleted. There is no schema, file-format, OAuth, path, or provider-setting change. No Dropbox credentials were available, so only non-sensitive synthetic data and mocked contracts were used.

### Rollback

Revert the implementation commit. No migration or provider-side cleanup is required. Rolling back restores unbounded pagination behavior and should only be considered if a legitimate account exceeds the configured limits.

### Defect and fix

The point-placement handler exited drawing mode but never replaced the earlier success live-region text. The UI therefore showed a settled selection while assistive technology was told placement remained active. A shared geometry-completion announcer now publishes the normalized feature type and whether Feature Details opened. Point, line, and polygon paths use the same completion contract; Dropbox retains its more authoritative save result.

Durable coverage: `test:geometry-completion-status` is required by Production CI and asserts point, line, polygon, detail-opening, and Dropbox-result behavior. Existing cancellation, desktop drawing, and mobile interaction checks remain green.

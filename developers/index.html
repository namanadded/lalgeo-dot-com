Agent-ready REST + OpenAPI

One predictable workflow

  1. Create a map.
  2. Add a Point, LineString, or Polygon layer.
  3. Post GeoJSON features to that layer.
  4. Export the finished map as a LalGeo project.
curl https://api.lalgeo.com/v1/maps \
  -H "Authorization: Bearer $LALGEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "id": "calgary_field_map",
    "name": "Calgary field map",
    "center": {"latitude": 51.0447, "longitude": -114.0719},
    "zoom": 12
  }'

Add real geography

Features use ordinary GeoJSON: longitude first, latitude second. A layer enforces one geometry type so agent mistakes fail early and clearly.

curl https://api.lalgeo.com/v1/maps/calgary_field_map/\
layers/places/features \
  -H "Authorization: Bearer $LALGEO_API_KEY" \
  -H "Content-Type: application/geo+json" \
  -d '{
    "type": "Feature",
    "id": "central_library",
    "geometry": {
      "type": "Point",
      "coordinates": [-114.0510, 51.0453]
    },
    "properties": {"name": "Central Library"}
  }'

Client-supplied IDs make agent retries safe and understandable. Duplicate IDs return 409 ID_CONFLICT instead of silently duplicating data.

POST/v1/maps/{mapId}/layers/{layerId}/features
GET/v1/maps/{mapId}/export

Designed for safe automation

Every data route uses a bearer API key. Keys are stored only as SHA-256 hashes, each key sees only its own maps, batches are limited to 1,000 features, bodies to 2 MB, and list responses are paginated. Errors return stable codes and a request ID.

One predictable workflow

  1. Create a map.
  2. Add a Point, LineString, or Polygon layer.
  3. Post GeoJSON features to that layer.
  4. Create a one-time link to open an editable local copy in Maps.
curl --fail-with-body https://api.lalgeo.com/v1/health

curl --fail-with-body https://api.lalgeo.com/v1/maps \
  -H "Authorization: Bearer $LALGEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "id": "calgary_field_map",
    "name": "Calgary field map",
    "center": {"latitude": 51.0447, "longitude": -114.0719},
    "zoom": 12
  }'

Add real geography

Features use ordinary GeoJSON: longitude first, latitude second. A layer enforces one geometry type so agent mistakes fail early and clearly.

curl --fail-with-body https://api.lalgeo.com/v1/maps/calgary_field_map/layers \
  -H "Authorization: Bearer $LALGEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "id": "places",
    "name": "Places",
    "geometry_type": "Point"
  }'

curl --fail-with-body https://api.lalgeo.com/v1/maps/calgary_field_map/\
layers/places/features \
  -H "Authorization: Bearer $LALGEO_API_KEY" \
  -H "Content-Type: application/geo+json" \
  -d '{
    "type": "Feature",
    "id": "central_library",
    "geometry": {
      "type": "Point",
      "coordinates": [-114.0510, 51.0453]
    },
    "properties": {"name": "Central Library"}
  }'

Always send stable IDs. If a request times out, read that ID before retrying. A duplicate returns 409 ID_CONFLICT instead of silently duplicating data; automatic Idempotency-Key replay is not available yet.

Open the result in Maps

Ask for a one-time link when a person is ready to open the map. The link lasts 10 minutes by default and never longer than 15 minutes. Opening it imports an editable local copy; later edits do not write through to the API map.

curl --fail-with-body --request POST \
  https://api.lalgeo.com/v1/maps/calgary_field_map/open-links \
  -H "Authorization: Bearer $LALGEO_API_KEY" \
  -H "Content-Type: application/json" \
  --data '{"expires_in":600}'

The response contains open_url and expires_at. Open the URL, then choose Open editable copy in Maps. Only that explicit click redeems it. If the link expired or was already used, request a new one.

Secure handoff: the URL fragment contains a random 256-bit capability, not the bearer key. Browsers exclude fragments from HTTP requests and referrer headers. The API stores only the capability's SHA-256 hash, Maps removes it from the address bar before showing the confirmation, and invalid, expired, or reused links all return the same non-disclosing error.

For a file workflow, GET /v1/maps/{mapId}/export still downloads a portable project. If the API map has no layers, either kind of copy starts with an editable Points layer without changing the API map.

Designed for safe automation

New authoring keys are operator-provisioned, scoped, and expiring, and every authoring route enforces HTTPS. Every scoped key includes maps:read for protected GET requests and export; add maps:write only when the key must POST, PATCH, DELETE, or create a one-time open link. Write access is never issued without read access because update responses and map handoffs contain existing map data. Existing full-access keys remain compatible during controlled rotation. Missing, invalid, and expired keys share the same 401 response. A read-only key used for a write receives 403 INSUFFICIENT_SCOPE. The public redemption route accepts only a short-lived, single-use map capability; the bearer key never reaches Maps or the link. The service stores only SHA-256 hashes, each key sees only its own maps, batches are limited to 1,000 features, bodies to 2 MB, and list responses are paginated. Errors return stable codes and a browser-readable request ID.
